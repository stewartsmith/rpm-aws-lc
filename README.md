# aws-lc

RPM packaging for [AWS-LC](https://github.com/aws/aws-lc), a general-purpose
cryptographic library maintained by the AWS Cryptography team and derived from
Google's BoringSSL and OpenSSL.

This repository holds the spec file, patches, and source manifest only; the
upstream tarball is fetched rather than committed.

## Layout

| Path | Purpose |
| --- | --- |
| `aws-lc.spec` | Package definition |
| `sources` | SHA512 manifest of the upstream tarball |
| `*.patch` | Downstream patches, applied in spec order |
| `aws-lc-provider.cnf` | OpenSSL config snippet that loads the provider |
| `changelog` | Curated changelog entries, appended by `%autochangelog` |

## Packages

- `aws-lc` — `aws-lc-bssl`, `aws-lc-openssl` and `aws-lc-c_rehash` tools
- `aws-lc-libs` — `libcrypto-awslc.so` and `libssl-awslc.so`
- `aws-lc-devel` — headers, pkg-config files, linker symlinks and the
  generated Rust bindings used by the `aws-lc-sys` crate
- `aws-lc-provider` — an OpenSSL 3 provider (`ossl-modules/awslc.so`) backed
  by AWS-LC
- `aws-lc-doc` — HTML API reference generated from the public headers

Libraries and headers are name-suffixed and installed under `aws-lc/`, so the
package coexists with the system OpenSSL instead of replacing it. The
libraries are built with crypto-policies support and read the
`aws-lc.config` back-end generated by `crypto-policies`.

## Tests

`%check` runs upstream's unit tests via `util/all_tests.go` (`crypto_test`,
`ssl_test`, `bssl_tool_test`, `tool_openssl_test`, `dynamic_loading_test` and
the isolated mem, rand, DRBG and rwlock binaries), followed by the provider tests and the provider linkage check.

Upstream keeps the tests that need the network (the `s_client` and OCSP
integration tests) in a separate `integration_test` binary that
`all_tests.go` does not run, so no test filtering is needed.

It does not run the other two legs of upstream's `run_tests` target: the
`ssl/test/runner` TLS suite (a fork of Go's `crypto/tls` that handshakes
against `libssl` through `bssl_shim`) and, on FIPS arches, the ACVP tests.
Both import `golang.org/x/crypto`, and with no vendor directory they cannot be
built in a network-isolated buildroot. That dependency is also the only reason
`go.mod` requires `golang.org/x/crypto`; nothing we ship uses Go.

## FIPS mode

FIPS mode is enabled only on the architectures AWS-LC supports it on —
`x86_64`, `aarch64`, `ppc64le`, and 32-bit arm — and disabled everywhere else.
The gate is upstream's: `util/fipstools/acvp/modulewrapper/main.cc` fails the
build with `#error "FIPS build not supported on this architecture"` on any
target it does not recognise, which is what `s390x`, `riscv64`, `i686`, and
`loongarch64` hit. The arch list lives in the `fips_arches` macro in the spec.

## Building

```sh
spectool -g aws-lc.spec    # fetch the tarball listed in sources
rpmbuild -ba aws-lc.spec
```
